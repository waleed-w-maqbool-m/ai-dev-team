About this project

The motivation, the architecture, and what each agent is actually responsible for.

Why this exists

A working demonstration of a five-agent software delivery pipeline built on LangGraph. Control flow is decided by code reading structured state — never an LLM guessing what happens next — and every loop is bounded so the system is guaranteed to terminate. This console runs against a real local FastAPI backend, not a scripted demo.

Deterministic routing Bounded retry loops Executed code verification Pluggable LLM backends Live local backend

How it works

One shared state, no peer-to-peer chatter between agents — each one reads a scoped slice of the same state and writes its result back to it, and a plain Python router (never a second LLM call) decides what happens next. A request moves forward through the five roles below until every task is done or explicitly set aside for a human, at which point the write-up gets produced.

What each agent does

Project Manager

Breaks the request into scoped tasks with testable acceptance criteria, and is the only agent authorized to decide the project is complete.

Software Engineer

Implements one task at a time and submits a diff — never judges its own work. If a task is genuinely ambiguous, it asks the PM once rather than guessing.

Testing Agent

The one agent that isn't an LLM call — runs real subprocess checks (syntax parse, import, an entry-point smoke-run) and files the results as evidence, with no say in routing.

QA Reviewer

Reviews the code against each acceptance criterion individually, weighing the Testing Agent's evidence — a failing test report is treated as strong grounds to return the work, under a bounded retry cap.

Documentation

Writes the README/changelog updates and the final user-facing summary once every task is done or set aside for human review.

Backend: a LangGraph state machine — deterministic routing, bounded retries, no idle debate. LLM_PROVIDER=ollama|groq
